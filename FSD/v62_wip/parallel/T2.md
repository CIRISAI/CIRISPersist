## 0d. v7: the race closed (conditional reap)

- **`BlobWriteStore::delete_blob_unless_claimed`** (new trait method, sqlite + pg). The inherent `delete_blob` becomes `delete_blob_guarded(sha, unless_claimed)`. In the SAME write transaction as the delete it asks whether a `custody:ack:v1` `here` row cites the blob (the holder index's own predicate: dimension, `evidence_refs[0]`, `custody_state`). If one does, nothing is deleted (`Ok(false)`, rolled back). Otherwise it runs `delete_blob`'s deletes unchanged.
- **`put_blob_edition2` uses it on a refused claim.** It also closes the other side: after its own claim is admitted, a writer whose bytes a concurrent reap removed in between re-stores them (`store_planned_blob` with the same plan, first-write-wins). So an admitted claim always finds its bytes held.
- **sqlite:** writes are serialized, so the guard and the delete are atomic.
- **pg:** the guard sees claims committed before it (READ COMMITTED); a claim committing after it is covered by the claimant's re-store. Residual: none believed.
- **Conn model:** the row `("delete_blob", Write)` is renamed to `("delete_blob_guarded", Write)`, because the inherent `delete_blob` now delegates (otherwise `no_conn_class_row_is_stale` / `every_connection_touching_fn…` red).

## 1. Design

`ingest::put_admitted_row` sends a non-composer row of the 7 families to `edition2::typed::put_typed_statement`. The intercept sits after T1's group branch and O1's occurrence branch, before the key plane. Each family reaches the JSON form's own door, with the payload mapped onto the typed struct and no embedded signed object:

| family | door | lands | counted |
|---|---|---|---|
| `identity:occurrence_revocation` | the carrier's structural rule, now SHARED primitives (`occurrence_revocation_carrier::{is_single_signer_identity, roster_majority}`), plus `check_signer_acts_for` on each voice's signing key; then `put_identity_occurrence_revocation_local` unless the pair is already revoked (attestation_admit's rule) | `federation_identity_occurrence_revocations` | for a user self: the voices' signing keys (`identity_ref(kid)`) ∩ `roster_now`, counted against the strict majority. Short → `Pending` (voice kept). A node/agent identity lands on one voice. |
| `revocation:{entity_type}:{reason}` | `put_revocation` (`plan_put_revocation`, every gate) under T1's vouch, through a new `Vouch::over(envelope, voices)` | `federation_revocations` | none (authored) |
| `takedown_notice:{basis}`, legal bases | `put_attestation`, with the envelope projected | `federation_attestations` | — |
| `takedown_notice:steward_purge` | none: the JSON row door is held shut (#988) | `ceg_statements`, `Pending` | the purge door counts |
| `custody:{kind}` | `put_attestation` (custody gate) | `federation_attestations` | — |
| `key_grant:{axis}` | `put_attestation`, then `project_key_grant_row` (for a new row AND a held one, as `attestation_apply` does) | + the grant tables or the pending index | — |
| `delivery_receipt:{stream_id}` | new trait method `put_delivery_receipt_edition2`, which runs the receipt door's JOIN and equivocation steps (`blob_admit::store_receipt_checked`, shared with `put_delivery_receipt_planned`); then the signed row through `put_attestation` (`signed_receipt_at` reads it) | `federation_stream_delivery_receipts` + `federation_attestations` | — |
| `cosign:{pending,signature}` | none: the hold IS the counted row (CC 3.1.3); `refs.target` must be held | `ceg_statements` only, `Voice` | — |

**Envelope projection.** `attestation_of` calls `typed::project_envelope(row, o)`, which renames the edition-2 members back to the names the earlier gates read. It reads from the PAYLOAD, so it is idempotent and safe beside cut B's digest-hex pass.

- takedown: `claimant`→`claimant_key_id`; `content_holders`→`content_holder_key_ids`; `content_sha256` and `evidence_refs` → hex; adds `subject_kind: takedown_notice`.
- custody: `evidence_refs` → hex; `family_id`→`family_key_id`.
- key grant: `community`/`minter`/`owner` → `*_key_id`; `family_id`→`family_key_id`; `at_rest_sha256` → hex; `wrapped_dek` bytes → UTF-8 text.
- receipt: `chunk_root` → hex.

Put, `verify_carried` and `check_carried_projection` all run `attestation_of`, so they read one projection (I3144).

**Reading (BELIEVED, flagged to main):** `wrapped_dek` in edition 2 is the UTF-8 bytes of the earlier verbatim wrap text (`KeyGrantWrapV2` JSON).

## 7. Behaviour risks / not done

- **Verify's family model.** Every fixture signs row type `scores` with `author` = iss, as P1d's door cases do. If Verify reads `identity:occurrence_revocation` as counted-with-no-author, or refuses a non-roster signer, I3150 needs `author` dropped from `occurrence_revocation_payload`.
- **Counted occurrence-revocation voices** are signed AS the identity (`iss` = identity, `kid` = the roster key, O1's seat arm). A voice with `iss` = its own key is counted too, because the count is by signing key.
- **Steward purge:** voices are only kept. `purge_rows` still takes a `StewardPurgeNotice` with `ThresholdSignature`s; reading the edition-2 voices there is NOT done (cut B / purge owner).
- **Cosign is a reading** (sent to main): a cosign statement is a `Voice` beside its event and counts for nothing. If CC wants it counted, it must carry the event's header, which is T1's path.
- **Receipt order.** The receipt is stored before its attestation row. If the attestation gates refuse after the receipt landed, the receipt stays and the statement is not kept. A re-put settles it (the JOIN is idempotent on an identical root).
- **Key grant I3160** relies on a self-scope grant to the owner's bound occurrence passing `recipient_may_hold_key` and `check_sealer`. That is BELIEVED; if it reds, it is that gate's verdict, not a mapping fault (I3142 witnesses the mapping).
- **Takedown I3168** assumes no gate before `check_takedown_notice_row_admission` refuses a user key's `takedown_notice` row.
- **The `wrapped_dek` reading** (UTF-8 bytes) needs CC/P1 confirmation.
- **Producers.** Cut B's `draft_from_envelope` states earlier names, which P1d refuses for these families. The writers in `typed.rs` are the inverse it should call.
- Not done: the `.pyi` (no surface change), CHANGELOG lines, and the `evidence/cc_impl.tsv` rows for I3140–I3168.
