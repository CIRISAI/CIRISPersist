## What the ruling became in code

### (a) and (b): the payload

`identity:occurrence` (wire `identity:occurrence:v1`) has the payload the ruling lists.

- Required: `identity_key_id`, `occurrence_key_id`, `device_class`.
- Optional: `hardware_attestation`, `transport_destination`, `encryption_pubkeys`, `build_manifest_hash`, `valid_until`, and `build_manifest_ref` as `refs.also.cites`.
- Also optional, from the CC 3.3.6.2 member table: `transit_xwing_pubkey` and `onion_hop_xwing_pubkey` at the top level, and `onion_relay`.

The two id members are bound to the row:

- `author` must equal `identity_key_id`;
- the CWT `sub` must equal `occurrence_key_id`.

`build_manifest_ref` goes under `refs.also.cites` because `refs` roles are a closed CDDL set (`head`, `prev`, `target`, `also:{ack,cites}`, …). CC 3.3.6.2 cites a seat's key record the same way.

### (c): the signers

Each statement over one bind payload is a voice. Voices arrive one at a time.

1. **The occurrence key's own statement.** `iss` = `sub` = `occurrence_key_id`, signed by that key. It fills a new role, `occurrence_key` (party `sub`).
   - CC's vendored model (rc20, Verify 23.1.3 and 23.3.0) names no second signer for `identity:occurrence`, so without the role Verify refuses it `iss_not_in_role` (read-checked: `family.rs` `check_family`).
   - `edition2::occurrence::WithOccurrenceRole(&VendoredFamilyModel)` adds the role. The door reads every row through it; only this family changes (I3026). `TODO(verify-rc21)`: drop the overlay when Verify vendors the role.
   - This voice is held (`StatementOutcome::Voice`). It lands nothing alone.
   - If the voice has the role but is signed by another key of that identity (a rotation), it is refused `occurrence_voice_not_own_key`. No test covers this, because it needs a rotation fixture.
2. **The author's statement.** `iss` = `author` = `identity_key_id`.
   - If no own statement is held, the author's statement is refused with the retryable `federation_attester_key_unknown`, naming the occurrence key, and nothing is stored (I3022). Order is guaranteed: a node admits the own statement first, so it serves the own statement first.
   - Then the JSON door's rule set, reused rather than copied:
     - `admission::check_signer_acts_for(identity_ref(kid), identity_key_id)`: the genesis key unless it is evicted, an active occurrence, or a node through its owner binding;
     - `operational::check_skew_bound`.
   - The voice is stored, and then the bind lands or waits.
3. **CC 3.3.6.4, the two paths.**
   - The bind is a roster change when all of these hold: the identity is a user key, the occurrence key is a user key, the occurrence is not the identity, and the key is not already on `self_roster::roster_now`.
   - A roster change lands when a strict majority of the live roster has signed as the identity over the same payload. The proposer counts. Each roster key's approval is its own author statement, a counted voice in edition 2. Until then the outcome is `StatementOutcome::Voice`.
   - Any other bind lands on one author statement. That covers an agent or node occurrence, which is single-signer (CC 3.3.6.4), the self pair, and a re-assertion of a live key.
   - With a roster of one, the owner's approval alone lands it: the add-device flow.
   - The lone path (`W_self`) is NOT carried; see "Not done".
4. **Landing.** `FederationDirectory::put_identity_occurrence_edition2(OccurrenceBind)` writes the bind (`StatementOutcome::Row`, Python `"plane": "row"`):
   - it reuses `occurrence_admit::plan_occurrence` (the device class and encryption key gates, the row hash, the #446 route);
   - the new executor `OccurrenceStore::store_edition2_occurrence` does a last-signed-wins upsert plus the V161 history row;
   - `attesting_key_id` is the landing author key;
   - `signed_envelope` is `{"edition2_row_id", "author_key_id"}`;
   - `signature` is NULL;
   - no earlier-form `identity:occurrence:v1` pair row is minted;
   - then the route projection and the owner re-wrap, as the JSON door does.

### (d): way (d) in the key-of-issuer check

- A new field `HeldKeys.occurrences: OccurrenceSeats`, set by `HeldKeys::with_occurrences`.
- In `key_of_at_depth`, right after `let iss_ref = identity_ref(iss);`, the seat answers `KeyOf::Yes`.
- `ingest::held_keys_for(dir, statement)` (every door, `verify_carried`, `carried_identity_type`, `cosign`) loads the seat with `occurrence::occurrence_seats_for`. It does so only when the statement's `kid` is not the genesis key of its `iss`, and only for that one pair `(iss, kid)`.
- **Liveness is read at the statement's own `asserted_at`.**
  - `occurrence_live_at` covers every admitted assertion of the pair (the V161 history and the held row) with `crate::kernel::key_end::within_record(at, from, until)`, K1's half-open rule. It applies the #421 revocation rule: a revocation in effect at `at` that came at or after the assertion ends it, and a later assertion re-establishes it.
  - When the key is no longer live at receipt (revoked or evicted since), the statement's `asserted_at` must be within W of this node's clock (CC 3.3.6.4: "an evicted key can backdate an owner act into its old live window by at most W").
  - A revoked occurrence (`identity:occurrence_revocation` in effect) or one past its end gives no seat, so the key-of-issuer check answers `kid_not_of_iss` (I3021).
- **It composes with C3.** C3's `impl KeyDirectory for HeldKeys` (and `Scoped`/`RecordsOnly`) calls `key_of_at_depth`, so Verify's own reader, the door and every caller get the same arm. My hunk is in `key_of_at_depth` at lines ~366–375, outside C3's hunks (351 and 392+). Checked with `git apply --check` on syn0+C3: liveness.rs applies.
- **The identity-set exclusion (update 2).** In `occurrence_seats_for` (`occurrence.rs`), when `iss`'s key types are a person's (`user` / `accord_holder`) and the signing key's are a machine's (`node` / `agent`), no seat is given, whatever occurrence row is held. The types are read from the `federation_keys` projection of each key's edition-2 record. The pair always matches `identity_key_id == iss`, because `occurrence_live` filters the held rows by the identity. So an agent key signing as its owner's identity is `kid_not_of_iss` (I3030 (d)).

- **One key per commitment (update 3; read-checked).**
  - CC v1.0-rc20 states that each `recovery_commitments` value is "the CC 3.2 T3 commitment over the holder's one recovery key, its composite COSE key exactly as stored on its key record" (part_2 l.66 and l.732; CC 4.2.6), with one entry per holder (`{ + identity-ref => hash-digest }`).
  - Verify 23.3.0's reader opens every commitment over one key: `recovery_commitment(core::slice::from_ref(rk))` at `edition2/genesis.rs` 1466, 1676 and 1747.
  - O1 matches the same way, so a several-key digest never counts a recovery and never catches a signer. I3031 pins this reading (pure).
  - The ruling asked for an assertion at bundle read. That cannot be built: a commitment is an opaque SHA-256, so no reader can see how many keys it covers. The one-key rule holds because CC and the reader both read it that way, and no code path opens a set. This is written in `recovery_signer.rs`'s module docs.
- **Ordering (update 3).** The check is a directory read, so it runs after the pure statement gates and before every key lookup, on both entries:
  - `ingest::put_statement`: right after the form check, which P1c replaces with `pure_statement_gates(bytes, &HeldKeys::new())`. Synthesis should keep O1's call right after P1c's line. It runs before the halt branch's roster read and before `held_keys_for`.
  - `ingest::verify_carried` (new in update 3): after P1c's `pure_statement_gates(&bytes, ..)` and before `held_keys_for`. The JSON door's mapped rows re-verify their carried statement there, so a mapped row cannot bypass the check.
  - It is not inside `held_keys_for`. That would make a cosign fold (`cosign.rs` ~1500) error forever on a voice held before a later bundle committed its key.
- **Cost (update 3).**
  - `recovery_keys_in_force` makes ONE directory read per statement: the held bundle voices (`edition2_objects(ceg-genesis-bundle/2)`). Pre-genesis it is empty and the check returns.
  - The derived `RecoveryKeys` is cached process-wide, keyed by the SHA-256 of the sorted voices: 8 entries, and only for readings with a Valid bundle. On a miss it calls C1's `genesis_in_force` (named-row reads plus Verify's reader, itself content-cached) once per held bundle set.

## Server adoption

Server produces two (or more) `COSE_Sign1` row statements over ONE payload and offers each to the door. The own statement goes first.

The payload, with CDE map keys in deterministic order (`ciris_verify_core::edition2::sign_row_statement` orders them):

```
{
  "asserted_at":        uint ms,                       ; required
  "author":             <identity-ref of the identity>, ; = identity_key_id
  "identity_key_id":    <identity-ref of the identity>,
  "occurrence_key_id":  <identity-ref of the device or agent key>,
  "device_class":       "phone" | "laptop" | "server" | "embedded" | "agent" | "service",
  ? "valid_until":      uint ms (> asserted_at),
  ? "hardware_attestation": bstr,
  ? "transport_destination": { "reticulum_x25519_pubkey": bstr32, "reticulum_ed25519_pubkey": bstr32,
                               "app_name": tstr, "aspects": [* tstr], "destination_hash": bstr16 },
  ? "transit_xwing_pubkey": bstr1216, ? "onion_hop_xwing_pubkey": bstr1216,
  ? "onion_relay": {"opt_out": true},
  ? "encryption_pubkeys": { "x25519": bstr32, "ml_kem_768": bstr1184 },
  ? "build_manifest_hash": [-16, bstr32],
  ? "refs": { "also": { "cites": [ row-ref of the provenance:build_manifest row ] } }
}
```

The protected header of every statement has row type `scores`, family `identity:occurrence`, and CWT `sub` = `occurrence_key_id`.

1. **The occurrence key's statement, first.** Signed by the new device's (or agent's) own composite key, with `iss` = `occurrence_key_id` (its own identity-ref). In Rust: `sign_row_statement(&device_key, &occ_ref, &occ_ref, "scores", "identity:occurrence", &payload, vec![])`. Persist's own signer gives the same with `edition2::produce::sign_row(signer, &occ_ref, "scores", "identity:occurrence", &payload)`, because `sign_row` sets `iss` to the signer's own identity-ref.
2. **The author's statement.** Signed by a live roster key of the identity (the genesis key, or an already-bound device), with `iss` = `identity_key_id`, the identity and not the signing key's own ref. **For an agent:** the occurrence binds the AGENT's identity (`identity_key_id` = the agent's identity-ref), and the OWNER authors it: `author` = the owner's identity-ref, `iss` = the owner, signed by a live roster key of the owner. In Rust: `sign_row_statement(&owner_roster_key, &owner_ref, &agent_occ_ref, "scores", "identity:occurrence", &payload, vec![])`. The agent's owner binding must be held first: `delegates_to` (row type) of the family `ownership:.relation:.target_kind:.version`, `sub` = the agent, `dimension` `ownership:responsible_party:agent:v1`, `author` = the owner, carrying the owner's statement and the agent's own. Without it the bind is refused `agent_occurrence_unowned`. If the agent identity authors its own bind, it is refused `agent_occurrence_not_owner_authored`. In Rust: `sign_row_statement(&roster_key, &identity_ref, &occ_ref, "scores", "identity:occurrence", &payload, vec![])`. `produce::sign_row` cannot set `iss` to another identity, so a device signing as its user needs `produce::row_protected(kid, iss, ..)` + `sign_composite` + `assemble`.
3. **The door.** Python: `engine.put_edition2_statement(own_statement)` → `{"plane": "voice", ...}`. Then `engine.put_edition2_statement(author_statement)` → `{"plane": "row", ...}`, or `"voice"` while a user self of two or more roster keys still needs a majority. In Rust: `Engine::put_edition2_statement(&bytes, None)`.
   - Offering the author's statement first is the retryable `ValueError("federation_attester_key_unknown")`. Offer the own statement, then retry.
4. **To add a device to a user who already has two or more roster keys**, each other roster key also signs the same payload as the identity (step 2 with its own key) until a strict majority of the live roster has signed.
5. **After the bind lands**, the device signs anything as the user (`iss` = the user's identity-ref, `kid` = the device key) and the key-of-issuer check admits it, until the occurrence is revoked or ends.
6. **Never produce** (CC 3.3.6, rc21; refused `occurrence_binds_machine_to_person`):
   - an occurrence under a user or accord-holder identity whose key is a `node` / `agent` key;
   - `device_class: "agent"` under a user identity.

   An agent key never signs as its owner's identity (`kid_not_of_iss`). It signs as the agent identity, and the owner's acts are the owner's own keys'.
