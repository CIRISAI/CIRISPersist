## Behaviour risks (things that will turn tests red for the right reason, or need a ruling)

- **Default ON flips every `seal_row*` caller in the suite**, builders or not (the brief's
  intent). Every such test now sees `attesting_key_id = kid(seed)` and a node-computed id.
- A row whose `dimension` Verify's matcher does not register (open vocabulary, `test:*`,
  `e7-fixture:` style) or refuses panics in the codec with the reason. These fixtures must
  move to a registered dimension (or be deleted as earlier-form witnesses).
- A `delegates_to` with no dimension is `self:delegates_to`; any other dimension-less
  non-composer row resolves its `attestation_type` as a dimension, else panics.
- `attestation_of` does not carry the `weight` column (pre-existing; J0). Fixtures asserting
  `weight == Some(1.0)` on a flipped row will see `None`.
- `row_of` admits with the signer's own `user` record (from 0) in memory; the STORE judges
  with what `put_key` stored. A test must `put_key` every signer before putting rows.
- Owner bindings: the node voice is not attached (an Attestation carries one statement).
  `voices_of(&row, &[&row.attested_key_id])` gives it; whether the store requires it before
  or after the row is slice A's door (not checked).
- Key records: a `user` / `accord_holder` record with an end panics (edition 2 has none;
  revoke instead). `signer_key_id` / `scrub_key_id` / `nonce` / roles are dropped (a key's
  record is self-signed). Node/agent records default to `today − 180 d` … `+365 d`.
- `put_public_key(SignedKeyRecord { record: key_row(..) })` is NOT how a key goes live; use
  `put_key` / `put_key_row` (the projection writer refuses an earlier-form row on the same id).
- `typed_family_row` with a non-row type now emits `scores` + dimension; the type-keyed
  witnesses (#543) are earlier-form and delete-candidates.
