## 1. What a test sees at `put_statement`

`ingest::put_statement` (and `e2::put_statement`, `apply_replicated_statement`) now routes a non-composer `group:roster` row, and a `membership:{stage}` row whose dimension binds leaf `widening` or `removal`, to `edition2::group::put_group_statement`. The typed row lands in its table through the JSON form's own door.

`StatementOutcome` gains one APPENDED variant:

```rust
StatementOutcome::Pending { row_id: RowId, new: bool }
```

- `Pending` means the voice is kept in `ceg_statements`, but no typed row exists yet. The voices are short of the group's protocol, or a founding roster lists a member who has not voiced it yet.
- `Row { row_id, new }` means the typed row landed: inserted, superseded, held as a K1 tip, or already held.
- An `Err` means the voice was **not** kept.
- Every voice of one version has the same `row_id`.

**Exhaustive matches to update (compile risk):** D1's and D2's `StatementOutcome` matches (`"key_plane" | "voice" | "row"`) need a `Pending` arm, for example `"pending"`.

## 3. Which typed-plane builders can now flip

How to flip one: keep the builder, and replace `dir.put_X(signed)` with `put_voices(dir, &X_voices(&signed, ..)).await`. Assert with `e2::kid(seed)`, because the typed row is keyed by identity-refs.

| builder (`tier_ingest::test_support`) | twin | can flip? | note |
|---|---|---|---|
| `sign_family` | `family_voices(&s, 1, None, at)` | **yes** | Every listed member must be a voice, which `sign_family`'s `founding_cosignatures` already gives. Each member must be a live edition-2 key (`e2::put_key`). |
| `sign_community` | `community_voices(&s, 1, None, at)` | **yes** | Same as `sign_family`. A node member of an infrastructure room is seated without a voice, as before. |
| `family_naming_held` | `family_voices_naming_held(dir, &s, at)` | **yes** | A later version needs the PRIOR roster's voices at its protocol. `sign_family` only gives the authority and the listed members. If the prior holders differ, add their keys with `roster_voices`. |
| `community_naming_held` | `community_voices_naming_held(dir, &s, at)` | **yes** | Same as `family_naming_held`. |
| `sign_family_membership_revocation`, `sign_community_membership_revocation` | `*_revocation_voices(&s, Some(&head))` | **yes** | `head` is the roster version's row id (`row_id_of(&roster_voice)` or `held_head`). A single voice that is short of the protocol is `Pending`. Add voices with `membership_voices`. |
| `sign_family_revocation_by_consensus`, `sign_revocation_by_consensus` | `*_revocation_voices(&s, Some(&head))` | **yes** | The co-signers become voices. |
| `sign_family_membership_widening`, `sign_community_membership_widening`, `sign_*widening_by_consensus` | `*_widening_voices(&s, Some(&head))` | **yes (v3)** | Hold the member's consent first: `let p = proposal_row(proposer, scope, group, member, role, t); e2::put_signed(d, &p)`, then `e2::put_signed(d, &acceptance_row(member, &p, t))`, then the widening voices (I3004). Without consent the widening is refused `membership_acceptance_unresolved` (I2999). |
| `sign_family` with a `supersede_proof` / `supersede_*_with_quorum` / `build_membership_change_envelope` + `ThresholdSignature`s | none | **rewrite** | See §6, the recipe. |
| dissolution versions (`dissolved_at`) | `family_voices(&s, v+1, Some(&head), at)` with `s.family.dissolved_at = Some(t)` | **yes (v3)** | The door builds the change envelope with the payload's `dissolved_at` (I3003). A dissolution changes nothing else. |
| `RosterCosignature` byte-level witnesses (bad cosig, duplicate cosigner) | none | **delete** | These are earlier-form proof shapes. In edition 2 a voice is a statement the door verifies (`edition2_statement_invalid`). |

## 6. Recipe: rewriting a supersede-proof / quorum test as an edition-2 version

The earlier form is a `SignedFamily` / `SignedCommunity` whose `supersede_proof` carries:

- `prior_persist_row_hash`;
- a `change_envelope` from `build_membership_change_envelope`;
- `quorum_signatures` (`ThresholdSignature`s over its JCS image) by the prior roster.

The test then calls `put_family` / `put_community` / `supersede_*_with_quorum`. In edition 2 there is no proof object. The version is its own row: it names the version it extends by `refs.head`, and every signer of the prior roster is one more voice over the same payload. The door builds the proof itself (the change envelope from this node's held state, plus `dissolved_at` when present) and counts the voices at the held head's `consensus_protocol`.

```rust
use crate::federation::edition2::fixture_switch as e2;   // + group_fixtures via the re-export

// 1. The held version's row id: track it from the put that landed it ...
let StatementOutcome::Row { row_id: head, .. } = e2::put_voices(d, &e2::family_voices(&v1, 1, None, t1)).await?
    else { panic!() };
// ... or find it from the store (it equals the head's `persist_row_hash` through its chain):
let (head, version) = e2::held_head(d, &e2::kid("fam")).await.expect("held");

// 2. The new record: what the earlier test passed as `new.family`. Drop the
//    `supersede_proof`; `prev_head_digest` is ignored (the door derives it from refs.head).
// 3. One voice per earlier quorum signer (the members of the PRIOR roster who signed):
let new = GroupRecord::Family(e2::family_with_kids(&new_family));
let signers: Vec<_> = ["alice", "bob"].iter().map(|s| e2::signing_key(s)).collect();
let refs: Vec<&_> = signers.iter().collect();
let voices = e2::roster_voices(&new, version + 1, Some(&head), t2, &refs);
//    (or, from a SignedFamily whose authority + cosignatures are the signers:
//     e2::family_voices(&signed_new, version + 1, Some(&head), t2))

// 4. Put them; read the outcome.
match e2::put_voices(d, &voices).await? {
    StatementOutcome::Row { .. } => { /* head moved (or held as a K1 tip if refs.head is not the head) */ }
    StatementOutcome::Pending { .. } => { /* short of the held head's protocol: a later voice completes it */ }
    other => panic!("{other:?}"),
}
```

How each earlier assertion maps:

| earlier assertion | edition 2 |
|---|---|
| the quorum short → `InvalidArgument("...consensus_protocol not met...")` | `Pending` (the voice is kept); the head does not move |
| a bad / foreign `ThresholdSignature` is not counted | no such object: a voice either passes the edition-2 door (`edition2_statement_invalid`, `kid_not_of_iss`) or is not held. A non-member's voice is not counted (the vouched signers ∩ the prior roster). |
| a stale proof (`prior_persist_row_hash` ≠ held) → `Conflict` | `refs.head` names a held older version → a K1 tip (`list_group_tips`); `refs.head` unheld → `federation_withdraws_target_unheld` (retryable) |
| `supersedes.prior_member_key_ids` mismatch (anti-replay) | cannot be expressed: the door builds the envelope from held state |
| an amendment adds a member → `membership_supersede_cannot_add` | unchanged (the same door): `MembershipAcceptanceRefused { rule: RULE_SUPERSEDE_CANNOT_ADD }` |
| an entrenched protocol changed → refused | unchanged (the same door) |
| dissolution: `change_envelope.dissolved_at` == the record's | set `dissolved_at` on the record; the door copies it into the envelope (I3003). A mismatch cannot be built. |
| `version` returned by `supersede_family_with_quorum` | `list_group_versions(cohort, group)`; the payload's `version` must be the head's + 1 (else `edition2_payload_invalid`) |
| `group_history` / `federation_group_versions.change_authorization` | holds the door-built `{change_envelope, quorum_signatures: []}`; the voices are in `ceg_statements` under the version's row id (`edition2_voices`) |

Tests that pin earlier-form-only shapes are delete-candidates (CONTRACT): the JCS bytes of the change envelope, the `ThresholdSignature` verification, a `RosterCosignature` byte-level forgery, and a duplicate co-signer.

## 7. v4: healing a fork (a merge)

```rust
pub const FURTHER_HEADS_ROLE: &str = "further_heads";
pub fn roster_payload_merging(record: &GroupRecord, version: u64, head: Option<&RowId>, further: &[RowId],
                              asserted_at_ms: u64) -> Result<Value, Error>;
pub async fn merge_reading<F>(dir: &F, view: &RosterView, row_id: &RowId) -> Result<MergeReading, Error>;
pub struct MergeReading { pub prev: String, pub merged: Vec<String> }
// group_fixtures (e2::*)
pub fn merge_voices(record: &GroupRecord, version: u64, head: &RowId, further: &[RowId], asserted_at_ms: u64,
                    signers: &[&CompositeSigningKey]) -> Vec<Vec<u8>>;
// FederationDirectory
async fn drop_group_tips(&self, cohort: Cohort, group_key_id: &str, persist_row_hashes: &[String]) -> Result<(), Error>;
```

**Recipe.** While a group is forked, its roster is the members common to all tips. To heal it:

- put a version `max(named versions) + 1` naming one tip by `refs.head` and the others by `refs.further_heads`;
- give it one voice per member of the common roster, enough to meet the head's protocol;
- the version lists no member outside the head record ∪ the active roster (#955 Q2, the same door).

`Row` means it is the one head, and the named tips have left `list_group_tips`.
