## Update 5 (genesis seats in the occurrence table, inside the transaction)

- **Phase 1 (pure):** for each admitted seat binding, C1 builds O1's
  `OccurrenceBind { occurrence: occurrence::read_payload(row)?, author_key_id:
  identity_ref(row.kid), row_id }` and plans it with O1's
  `occurrence_admit::plan_edition2_occurrence(bind)` (device class,
  encryption keys, row hash, the route). The result goes into
  `GenesisWrite.occurrences: Vec<PlannedOccurrence>` (a `pub(crate)` field).
- **Phase 2:** `put_edition2_genesis` writes each planned occurrence inside
  the same transaction:
  - sqlite: `sqlite_store_edition2_occurrence(&tx, planned)`;
  - pg: `self.pg_store_edition2_occurrence(&tx, planned)`.

  Both are O1's tx-level helpers: no inner transaction, no commit.
- **After the commit:** the route each binding projects goes through
  `transport_routes::project_occurrence_route(dir, route)` (the
  `put_transport_destination` door, whose displacement gates read the store).
  A failure there leaves the genesis held and the route re-projectable. For a
  genesis seat the pair is identity == occurrence, so there is no epoch
  re-wrap. If O1 provides tx-level route helpers (asked), move them into the
  transaction.
- **ASSUMED APIs (O1; proposed to O1 by message, not yet confirmed):**
  - `occurrence_admit::plan_edition2_occurrence(OccurrenceBind) ->
    Result<(PlannedOccurrence, Option<TransportDestination>), Error>`;
  - `fn sqlite_store_edition2_occurrence(tx: &rusqlite::Connection, &PlannedOccurrence)
    -> Result<bool, Error>` (free fn in sqlite.rs);
  - `PostgresBackend::pg_store_edition2_occurrence<C: GenericClient + Sync>(&self, tx: &C,
    &PlannedOccurrence) -> Result<bool, Error>`;
  - `occurrence::{read_payload, OccurrenceBind}` (in O1.patch, read-checked
    there: `read_payload` is `pub fn`, the `OccurrenceBind` fields are pub).

  If O1 publishes other names, synthesis renames the three calls.
- **Witnesses:**
  - I2314 now asserts each seat of the placed first bundle is in the
    occurrence table (`list_identity_occurrences_for`).
  - I2320's fault half snapshots S1's occurrence rows before the faulted
    re-seat and asserts they are unchanged after it. The re-seat binding (a
    newer `asserted_at` on the same pair) would have replaced them, so NO
    occurrence row stays.
- **Expected re-vendor reds:** unchanged (update 4 list).
- **Requires** O1's patch in the same lane as C1 (`edition2::occurrence`,
  the helpers above).

## Update 4 (the import is all or nothing)

- **Phase 1, no writes.** Verify places every offered bundle first. Then,
  for each Valid one, each named row not held passes `admit_named`, under the
  keys the bundle places (`BundleKeys`):
  - `door::admit_row` and `payloads::check`;
  - for a seat binding (`identity:occurrence`), the occurrence door's
    store-reading gates, answered by the placement:
    - acts-for: the binding's `iss` must be a placed seat's identity-ref, and
      its `kid` that seat's placed key;
    - the clock-skew bound: `operational::check_skew_bound` against
      `host::clock::now()`.

  Then each placed key's read model is derived (`plan_keys`). This reads the
  held key plane plus the offer's admitted key records, with
  `HeldKeys::with_seats(BundleSeats::held(placed holders, seats, witnesses))`:
  the placement answers whose each placed key is, which is what C2's recovery
  case and the re-seat need. The recovery key's own record is stored but NOT
  projected, since a recovery key is not a placed key.
- **Phase 2, ONE transaction.** NEW trait method
  `FederationDirectory::put_edition2_genesis(&GenesisWrite)` (foreign hunk in
  mod.rs; default `Unsupported`, so the regenerated double delegates it as a
  leaf, 142 delegations, `--check` OK). It is implemented on sqlite
  (`write_tx`) and pg (`client.transaction()`). In one transaction it writes:
  - every named row (`put_row_sqlite` / `put_row_postgres`: statement + names);
  - every key read model (`sqlite_upsert_edition2_key` / `pg_upsert_edition2_key`
    at `next_key_serve_position`, and the revocations);
  - every bundle voice (`put_object_*`);
  - then commits.

  `GenesisWrite { rows, keys: ProjectionSet, objects, fault: WriteFault }`.
  `WriteFault::BeforeCommit` (test seam) fails after every write, before
  commit, and the dropped transaction rolls back.
- `ingest::put_admitted_row` (update 3's foreign hunk) is REVERTED: ingest.rs is
  untouched again.
- `put_genesis_bundle` = `put_genesis_bundle_with(.., WriteFault::None)`; the
  `_with` form is `pub(crate)`.
- **Witness I2320 extended** (sqlite + pg). The counted re-seat
  (`reseat_seat_new_key`) with `BeforeCommit` gives the transaction's own
  error, and afterwards:
  - no voice of it, no new named row (the S1N record, the new binding);
  - no `federation_keys` row for S1N's identity-ref;
  - the bundle in force is still `first_valid`.

  The same offer without the fault is then placed.
- (superseded by update 5) **NOT in the transaction:** O1's typed occurrence row
  (`put_identity_occurrence_edition2`: the occurrence table, its history,
  the route projection, the owner's epoch re-wrap). O1's write opens its own
  transaction (`store_edition2_occurrence`) and is followed by async steps, so
  it cannot join this one without an O1 refactor into a tx-level helper. A
  genesis seat's binding is therefore held in `ceg_statements` only, and its
  transport keys are read from the placement (`GenesisPlacement.seats[].{
  transit,onion_hop}_xwing_pubkey`, C2's serve-transport re-derivation). If
  the occurrence table must hold genesis seats, the synthesis lane adds an O1
  tx-level helper and puts it in `GenesisWrite`.
- **Expected re-vendor reds (unchanged reason):** with P1 applied, every store
  witness that places a vector bundle is refused `edition2_payload_invalid`
  until the re-vendor adds the occurrence members to Verify's vector bindings:
  I2314–I2320 (I2320's fault half included: phase 1 refuses before the
  transaction, so its "injected fault" assertion reds), and the entrenched
  half of I2321. Pure replays (I2301–I2304) and I2322 are unaffected.
- Compile risks added: `next_key_serve_position(&tx)` and the
  `pg_upsert_edition2_key(&tx, ..)` generic `C` with a deadpool
  `Transaction` (the existing `upsert_edition2_key_projection` does the same,
  read-checked); `GenesisWrite` derives `Default` (all fields default,
  read-checked).

## Update 3 (CC ruling (a): the bundle import gates named rows) — storage part superseded by update 4

- `put_genesis_bundle` NO LONGER files named rows structurally (`named_row` /
  `store_named_rows` deleted). For every offered bundle Verify reads Valid,
  and BEFORE anything is stored, each named row not already held passes:
  - `door::admit_row(bytes, &BundleKeys, Some(row_id), SelectContext::default())`
    (form, size, Verify's verdict in its family through the door's model,
    the key-of-issuer check, the row id, the key-record end rule);
  - `payloads::check(family, payload)` (the closed member list; P1's table).

  `BundleKeys` is a `KeyDirectory` holding the keys the bundle places
  (holders, seats, witnesses) and each named `key:record`'s own key, with
  `key_of` = Yes for a placed key (Verify's own `PlacedKey` rule; Verify has
  already judged whose each key is).
- Any refusal refuses the WHOLE offer under the row's own token (reused, no
  new token), the message naming bundle and row; nothing is stored.
- Then each named row is stored through `ingest::put_admitted_row` (NEW, a
  FOREIGN hunk in ingest.rs): `put_statement`'s post-admission tail split out
  unchanged (composer target, key plane + projection, further voice, row
  through attestation gates). O1's occurrence dispatch, inserted in that tail,
  therefore also runs for a bundle's seat binding. The original
  `check_composer_target(dir, &admitted)` line is kept byte-identical so
  O1's hunk context still applies (clippy may flag `needless_borrow`).
  Key-plane rows are stored first.
- New witness **I2322** (sqlite + pg): `first_valid` whose seat binding lacks
  `device_class` → `edition2_payload_invalid` (message names
  `identity:occurrence`), no voice and no named row stored, still pre-genesis.
  The helper uses the vendored binding as is when it lacks the member (Verify
  23.3.0's vectors lack all three occurrence members), else re-signs the
  binding with the seat's test key without it, re-cites and re-signs the
  bundle with the holders' test keys (keys n per Verify's `_meta.keys`).

## Behaviour risks for the S1 lane

- (update 3) named `key:record`s are stored via `put_admitted_row`, which
  calls `projection::project_key` and propagates its error. A holder record with an attestation
  chain, or a re-seat record (iss = the seat's identity-ref, kid = new key),
  may not project cleanly (the key-of-issuer seat arm is not wired, below);
  if I2314/I2320 fail there, the honest fix is in projection (or skip
  projection for a record the key plane cannot read), not in the door.
- (update 3) Named rows now pass their own door; see Update 3.
- Every door call re-reads every held bundle with full crypto (cache only on
  `genesis_in_force`). Fine for genesis cadence.
- The process-wide test root registry adds the vector mock roots for the
  whole lib test process (no persist test asserts the baked roots refuse
  them today).
