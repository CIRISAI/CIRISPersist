## How the call sites flip (one recipe everywhere)

- Keys: `register_hybrid_key*` / `register_identity_key` / hand-built `KeyRecord` + `put_public_key` → `e2::put_key(dir, seed, &[type])`, which returns the identity-ref. Queries and assertions use `e2::kid(seed)`.
  - E0 v1.2 also flips the `register_*` helpers in place to the same meaning. My explicit calls are equivalent; read-checked against E0.api.md v1.3.
- Rows built as literals: an earlier-shaped, UNSIGNED `Attestation` (`e2::with_earlier_form(|| ts::bare_attestation(..))` where a builder made the skeleton), mutated, then `e2::try_put_row(dir, &row, seed)`. The returned row id is `e2::rid(&stored)`.
- Composers with no dimension (`withdraws`) go through `e2::statement_of_family(&w, seed, &e2::family_of(&target))` + `e2::put_statement`, or through `e2::composer_of`. The target row is read from the store first.
- Local-tier rows: `edition2::ingest::put_statement(dir, &e2::statement_of(&row, seed), None, attestation_tier::LOCAL)`. These replace the `attestation_upsert_local` / `attestation_insert_local` caller-signed inputs. The id comes from the `StatementOutcome` (`row_id.hex()`).
- Rows from flipped builders: `e2::put_signed(dir, &row)`. The owner-binding node co-signature is `e2::voice_of(&e2::carried_statement(&row)?, node_seed)` + `e2::put_statement`.
- Dimensions that are not a Verify family were moved to registered ones. I checked against Verify 23.1.3's vendored `data/cc/family_authorship.json` (184 families):
  - `identity_binding:v1` → `chat:dw_report:v1`;
  - `i1544:*` → `chat:i1544_*`.
