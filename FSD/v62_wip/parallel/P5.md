# P5: a serve seat needs an announced owner; agents are never exempt

Base: `v62-syn0` @ 8f33957f. Worktree `/home/emoore/CIRISPersist-wp-P5`, branch `v62-p-P5`. Patch: `P5.patch`. Invariant block I3110–I3139 (used I3110–I3113). Nothing was built, so every claim is BELIEVED. Claims marked "read-checked" were checked by reading the source.

## 1. Where the ruling came from, and what it requires

**The ruling.** `FSD/v62_docs/RULINGS.md` § "Security fixes and corrections in v62": "The infrastructure carve-out (no steward binding, no moderator, plaintext, Commons replication) requires a conformant `infrastructure` record that is rooted in THIS node's trust set. Agents are never exempt. A serve-seat node needs an announced owner. No 61.x patch. (Eric)"

**Its history** (memory log `project_final_refactor_fsd.md`, lines 112–116):
- E1 found that the carve-out was self-grantable through `substrate_persist`.
- CC answered that the carve-out is keyed on the community record, and listed the parts: "(b) Node seating on a conformant record + a live announced owner for a serve seat (CC 5.4.6; the test moves from admission to the seat)".
- 2026-11-15, Eric ruled no 61.x patch and "Agents ALWAYS need a steward-binding, infra included". He assigned this to E1 as item 9, with three parts: one predicate, removing the agent exemption, and the serve-seat announced-owner check (CC 5.4.6).
- E1 / cut A landed parts 1 and 2 (`is_authorized_infrastructure_community`; agent members refused in `check_community_membership_steward_binding`). The CHANGELOG v62 entry says the third part "was already enforced at the growth gate (`serve_seat_owner_unannounced`, v61)".

**The CC text** (rc20, `part_5_transport_substrate.md` §5.4.6 `announce-suppress`, read-checked at tag `v1.0-rc20`):

> A node that holds a `serve` seat in an `infrastructure` community MUST have an announced owner … While the node holds the seat, a live owner-binding for it MUST exist at `cohort_scope: federation`; it need not be part of the genesis and can be requested at any time. The test is evaluated live, never at a past instant (CC 2.7.5) … While no such binding exists the node does not serve under the seat, refused `serve_seat_owner_unannounced`; nothing in the genesis bundle or the holders' ceremony carries or seeds the binding, which is the owner's own row. A node that boots seated and owned but unannounced announces itself if its owner's key is present and otherwise raises an alarm. The substrate makes the check and the serving layer gates on it.

CC 3.2 (`part_3_the_namespace.md`, the steward-binding gate):

> An `agent` key MUST be steward-bound before it is admitted to an `infrastructure` community too. The one exemption is a `node` member of an `infrastructure` community … its owner is tested at its `serve` seat (CC 5.4.6) … With no owner, a key MAY trust and serve `infrastructure` communities and does nothing more … It holds no `serve` seat, which needs an owner who has announced the node.

**My reading.**
1. The owner test belongs to the **seat**, not to membership. An unowned node keeps the node-member carve-out: it may be a member of, trust, and replicate an infrastructure community. So I did NOT gate the membership carve-out on the owner. That follows CC 3.2 "With no owner, a key MAY trust and serve `infrastructure` communities". The lead's guess that the owner gates "the carve-out" is narrower than this text.
2. What an unannounced seat loses is **serving under the seat**: its serve standing.
3. v61 checks the owner only at the **growth gate**, when a widening seats an accord-scrubbed node in a community (`membership_acceptance::check_growth_accepted`, read-checked). Under ruling C a seat is membership in `serve_nodes` of the genesis bundle in force. CC says the bundle never carries an owner binding, so **every bundle seat starts unowned, and nothing checked its owner before it was granted canonical standing**. That is the gap I closed.
4. Rows are not withheld. A node's own `hard_case:*` and revocation rows are admitted whatever its serve standing. The text does not tie row admission to the owner, so I did not need to exempt accountability records: the rule never reaches them.

**What is refused or withheld**, for an edition-2 key (identity-ref) in `serve_nodes` of the bundle in force with no live owner binding at `federation`:

| reader | unannounced seat | announced seat |
|---|---|---|
| `admission::is_canonical` / `is_canonical_effective` (the SEAT) | true (unchanged) | true |
| `admission::serves_under_seat` (NEW) | **false** | true |
| `admission::seat_serve_standing` (NEW) | **false** | true |
| `trust_root::resolve_serve_tier` | **`None`** | `Canonical` (NEW rung) |
| `namespace::is_trust_root` / `holdings_authority` (corpus reach) | **false / `ProducerSteward`** | true / `AccordCoScrub` |
| its own rows (`hard_case:*`, …) | admitted | admitted |

## 2. "Agents are never exempt", checked at every carve-out site (read-checked)

| site | node exemption | agent |
|---|---|---|
| `admission::check_community_membership_steward_binding` (local + widening doors) | if `is_authorized_infrastructure_community` | never exempt (cut A) |
| `community_admit::plan_put_community` when the trust-root door said `true` | **skipped the whole gate** | **was admitted with no steward binding: FIXED** |
| `admission::check_no_moderator_federate_admission` | community-level, no member exemption | n/a |
| `community_dek` / `at_rest_cascade` / `replication_audience` | community-level (plaintext, Commons) | n/a |
| `membership_acceptance::node_seated_without_acceptance` (no acceptance) | node-bearing key with the accord's scrub | not node-bearing, so never seated this way |
| `kernel/consensus.rs` `infra` | counting (founders count), no exemption | n/a |

**The gap.** `plan_put_community` ran `if !trust_root { check_community_membership_steward_binding(..) }`. When a trust-root-grade record (an infrastructure room chained from an accord birth) passed `check_trust_root_at_door`, the gate was skipped for every member. `check_trust_root_shape` and `check_founders_eligible` constrain only the founders. So an unstewarded `agent` listed as a member was admitted. This is fixed: the trust-root door now runs `check_trust_root_membership_steward_binding`, which exempts node members on the door's verdict and never exempts an agent.

I did not reuse `is_authorized_infrastructure_community` at that door. Its (ii) reads the STORED chain (`rooted_community_family`), and a first put is not stored yet, so it would refuse the genesis room's serve node (fail-secure, but it breaks `rooted_infrastructure_room` and the canonical room). See Q2.

Hardening in the shared walk: a member whose identity set names `agent` beside `node` is not exempt. The key doors refuse such a set since v62, but a held row may predate that.

## 8. Not done / questions

- **Q1 (earlier-form canonical).** `seat_serve_standing` keeps the pre-v62 reading for an earlier-form key id: the v61 production canonical by co-scrub, with no owner check. Applying the owner rule there would demote the live v61 canonical's corpus reach and retention tier on upgrade if it has no announced owner. The re-mint at the ceremony moves it to a bundle/2 seat, where the rule applies. Should the earlier form be held to it too before the JSON doors close?
- **Q2 (rooted-here at the trust-root door).** The trust-root door exempts node members on its own verdict (a chain from an accord birth), not on "rooted in THIS node's trust set". On a re-rooted node whose trust edges name another root, a first put of an accord-rooted room still exempts its node members at the door. Later reads use `is_authorized_infrastructure_community`, which refuses. Applying (ii) at the door needs the root of the offered chain checked against `trusted_roots_of`. Is that wanted? It would make a re-rooted node refuse the accord's room.
- **Q3 (MeshServer).** The owner-conferred `MeshServer` rung already requires an owner (`owner_of`), but not an ANNOUNCED one. CC 5.4.6 scopes the rule to "a `serve` seat in an `infrastructure` community", and an owner's `infra:serve` grant is not such a seat. Left unchanged.
