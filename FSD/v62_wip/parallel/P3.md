# P3: the hard_case edition-2 projection (finding E6, the derived-id fence)

Base: `v62-syn0` @ 8f33957f. Worktree `/home/emoore/CIRISPersist-wp-P3`, branch `v62-p-P3`. Patch: `P3.patch`. Invariant block I3050–I3079 (used I3050–I3054). Nothing has been built, so every claim is BELIEVED; claims marked "read-checked" were checked by reading the source.

## The finding (confirmed by reading)

`project_hard_case_row` (`src/federation/hard_case.rs`) projected a row only when `attestation_id == hard_case_attestation_id(event_id)` (the v1 UUID) or `== hard_case_attestation_id_for_emitter(signer, event_id)`. An edition-2 row is stored under the row id the node computes, `SHA-256(CDE(["CEG-row/2", type, family, sub, author, payload]))` (`ingest::attestation_of`, `names::RowId::of_statement`), so no edition-2 hard_case row could ever project into `hard_case_events`. This is read-checked.

## What the fence protected

1. **The parts agree.** The id, the dimension and the body name one event, so a peer cannot file a body under an id that names a different event.
2. **Idempotence.** The same emitter re-recording the same observation names the same row, so the second write is a no-op.
3. **No pre-claim** (v61.1 H3). The emitter-bound id is bound to the signer, so another key cannot occupy the id this emitter's record lands under.

## The re-expression for edition 2 (`hard_case.rs`)

- **`project_hard_case_row`** now branches on whether the envelope carries `ceg_statement`.
  - **Absent (earlier form):** the old fence, unchanged. The local `record_hard_case` door (`plan_hard_case_row`) still builds these rows.
  - **Present:** the new private fn `edition2_hard_case_event(row, carried)`.
  - **Both branches:** the shared dimension check (`hard_case_dimension(kind) == dimension`) and emitter = signer.
- **`edition2_hard_case_event`** is pure, so the from-rows rebuild asks exactly what the live write asks. It projects a row only when all of these hold:
  - `RowId::of_statement(bytes).hex() == attestation_id`. The id is the statement's own, which covers properties 1 and 2: the payload is under the hash.
  - The header row type (-70001) is `scores`.
  - The payload's `author` equals `row.attesting_key_id`. `hard_case:{kind}` is an authored family in Verify's vendored model (read-checked in `data/cc/family_authorship.json`), so the author is in the id. Two emitters therefore always get two ids, which is property 3.
  - The envelope's `dimension` and `hard_case` members equal `json_of` of the payload's members. The event is read from the statement's payload.
- **`edition2_body_instants`:** a body `emitted_at` carried as POSIX ms (CC 2.6.2) is read as that instant; the text form is read as before.
- **Dedup in `hard_case_events`:** the table stays keyed on `event_id`. The existing `projection_outranks` (unchanged) picks the held row in every arrival order. An edition-2 id (64 hex) is never the v1 UUID, so it ranks as "emitter-bound", and between two such rows the lower id wins. One emitter's second statement for the same `event_id` with a different `asserted_at` is a second row (both kept, since accountability records are unpurgeable and nothing is deleted) but still one event. No new refusal token: the door already refuses an edition-2 row under a non-computed id (`edition2_row_id_mismatch` / `typed_diverges_from_envelope` in `verify_carried`).
- CLM-accountability-record-unpurgeable is untouched: the purge guards key on the `hard_case:` dimension prefix, not the id.

# P3 part 3: lead rulings applied (2026-11-18)

## Accepted

## Reals in `detail` (`P3-cutb.patch`, regenerated)

- **What edition-2 payloads allow (read-checked):**
  - CC 2.6.1.5 has no floats.
  - `edition2::emit::payload_from_envelope` → `cbor_of` refuses any non-integer number: "a real outside the fixed-scale members".
  - `SCALED_MEMBERS` (`ingest.rs:64`) = `score`, `confidence`, `weight`. They are top-level members at ×10⁶, written by `scaled()` as `round(x·10⁶)`.
  - `payloads.rs` on syn0 has no hard_case family and no real-typed member. There is no CDDL file on these bases: `docs/EDITION2_PAYLOADS.md` is generated from `payloads.rs`.
- **The new function:** `hard_case::edition2_reals(value, member) -> serde_json::Value` (pub, pure), which walks the body recursively.
  - A real under a member named in `SCALED_MEMBERS` becomes the fixed6 integer `round(x·10⁶)`, the same rounding as `scaled()`. An array under such a member inherits the member's name.
  - Any other real becomes its shortest decimal string (`serde_json::Number` `Display`, e.g. `"0.25"`). It is never rounded.
  - Integers, text, booleans and null are unchanged.
- **Where it applies:** `hard_case_emit_input` applies it to the `hard_case` body, so `state_hard_case` and `Engine::record_hard_case` emit no floats. The node-local row (`plan_hard_case_row`) keeps the event as built.
- **Read side:** a projected edition-2 event shows the stated forms (fixed6 integer or decimal string) in `detail`. The mapping rescales only top-level scaled members, so nested ones are not converted back.
- **Witness I3057** (pure, in `edition2/hard_case_producer_invariants.rs` `mod unit`):
  - `edition2_reals` maps `{score: 0.75, ratio: 0.25, count: 3, nested: {confidence: [0.5, 1]}}` → `{score: 750000, ratio: "0.25", count: 3, nested: {confidence: [500000, 1]}}`.
  - The emit input of an event with `detail {score: 0.5, drift: 1.5}` carries `{score: 500000, drift: "1.5"}` and builds a payload.
  - The same envelope with the float put back is refused by `payload_from_envelope`. This assumes `cbor_of` recurses into nested objects, which is BELIEVED and is what the refusal leg tests.

## `enter_mesh` restatement: NOT implemented, listed (it is not small)

The restatement would go in `Engine::enter_mesh`, before `custody_for`:

> when the row is local-tier, carries no statement, `project_hard_case_row(&row)` is `Some(event)`, and `row.attesting_key_id == self.local_derived_key_id()`:
> - call `state_hard_case(dir, self.composite_signer("enter_mesh")?, event)`;

This is not small, for three reasons:

1. **Which typed outcome to return.** `MeshCrossingOutcome::Crossed(MeshCrossing { attestation_id, audience, custody, age_at_crossing_ms, replicates })` needs a `Custody` and `Replicates` for a crossing that did not happen in place. `AlreadyInMesh` would mislead the caller, because the local row stays local.

3. **Re-sweep.** The local row never leaves the local tier, so each sweep restates it. That is idempotent (same bytes, `Voice { new: false }`) but repeated. A marker would be needed, for example flipping the local row's tier, or a "stated" column. That is a storage decision.

All three belong to B's crossing conversion (`custody_for` still signs the earlier form on cut B). The pieces it needs exist: `state_hard_case`, `hard_case_emit_input`, `project_hard_case_row`.

# P3 part 5: `asserted_at = max(emitted_at, key start)`; the placement-gate read (lead ruling, 2026-11-18)

## Risk 3 fixed (`P3-cutb.patch`, regenerated)

- **NEW `pub async fn hard_case::statement_instant<D>(dir, signer, emitted_at) -> Result<DateTime<Utc>, Error>`.**
  - It returns `max(emitted_at, start)`. `start` is the MINIMUM `asserted_at` among the signing key's valid edition-2 records (`held_keys_for_kid` + `HeldKeys::valid_records`) that cover NOW (`asserted_at <= now <= valid_until`, or no end). This is the same coverage test `HeldKeys::resolve` applies (read-checked, liveness.rs).
  - Taking the minimum over the records that cover now means a renewal that also covers now does not move `start`. A restatement is therefore deterministic per signing key across renewals while the earliest live record lives.
  - With no current record it returns `emitted_at`, and the door then judges the signer.
  - A signer without its PQC half fails with `composite_signing_unavailable`.
- **`hard_case_emit_input(event, asserted_at)`** now takes the instant. The body still carries the event's own `emitted_at`.
- **`stated_hard_case`** (shared by `state_hard_case` and `restate_held_hard_case`) computes `statement_instant` first.
- **Witness I3059** (`i3059_sqlite` / `i3059_postgres`, one engine):
  - An event with `emitted_at` one day before the node's `key:record` is stated and admitted.
  - The row's `asserted_at` is after `emitted_at` and not after now.
  - The body's `emitted_at` is the original instant.
  - A re-record gives the same row id.
- I3057's call is updated to `hard_case_emit_input(&event, event.emitted_at)`.
- Risk 2 is left as it was, as ruled: re-signing is idempotent.

## Risk 4: does a node-signed `federation` hard_case pass the placement gates? Read on cut B

Read-checked; the verdict is BELIEVED: **it passes on cut B.** The gates a `scores`, `hard_case:{kind}:v1`, `federation`-scoped, self-attested row signed by a `node` key meets on the put door:

- **`check_attestation_write_scope` → `check_write_cohort_scope_for`:** `federation` has no target plane, so it takes the fast path (`mod.rs:9047`). No roster or owner read.
- **`check_cohort_standing_resolved` / `check_promotion_cohort_standing`:** not a targeted cohort, so `Ok`.
- **`check_no_moderator_federate_apply`:** the candidates are the attester and attested endpoints (the node key), which are not a locally known community, so it fails open (`admission.rs:17421`). The infrastructure carve-out (`is_authorized_infrastructure_community`) is reached only for a known community, so it does not apply.
- **`check_reserved_prefix_admission`, `hard_case:` arm:** `node` is in `HARD_CASE_EMITTER_IDENTITY_TYPES`. Attester equals attested, so no `infra:record_hard_case` conferral is needed.
- **`DimensionAdmissionPolicy`:** no scope term. `node` is the identity persist's own door already signs with.
