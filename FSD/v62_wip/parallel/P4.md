**Shape of the fix (decided after the inventory):** the projection and `carried_identity_type` are LEFT carrying the record's own set (CC 3.4.7 says a key's kind reads "stand as written", and several readers use labels as non-authority cards or opt-ins: G9, G11, G12). Instead, the gates that GRANT on a label (G1–G4) are moved to the conferral plane for any row carrying an edition-2 statement. Stripping conferring labels from the projection was considered and rejected: it fails closed on readers whose label use is legitimate (WA cards, transit/serve opt-ins, publisher enumeration) without closing anything G1–G4 does not already close.

## The rule, from CC rc20 (read at tag v1.0-rc20, `part_3_the_namespace.md` 3.4.7 / 3.4.7.1, `part_4` 4.4.3.34)

- 3.4.7: "**No key declares itself into a duty.** `identity_type` on a key record is the key's own statement about itself. No admission decision reads it to open a reserved family."
- 3.4.7 table: `detection:*` → duty `infra:detect`, conferred by "a root the reader trusts", refused `reserved_family_unseated`. `accord:*` → "a standing accord holder", conferred by "the accord's charter" (CC 3.4.1), refused `federation_accord_dimension_requires_accord_holder`. `transparency_log:cosigned:*` → `infra:attest_assurance`; `age_assurance:*` → `assure:age`; `capacity_assurance:*` → `assure:capacity`; `system:*` → `infra:attest` from the node's owner (owner-binding).
- 3.4.7.1: "A conferral is not a label. A canonical key's `identity_type` is {`node`}; its canonical standing is the accord's counted conferral ... `substrate_persist` is a key type that confers no authority."
- 4.4.3.34: "A reserved duty, such as `infra:detect` for `detection:*`, is conferred on the **delegation** plane."

So detector standing is NOT a key type and NOT a seat: it is the `infra:detect` delegation from a root the reader trusts. Persist already resolves that walk (`trust_root::capability_roots_to_trusted_root`); the gap is that the edition-2 path never reaches it for the dimension shape, and reads the self-declared type instead.

- **Q1 — the assurance scopes.** CC rc20 3.4.7 names `assure:age` for `age_assurance:*` and `assure:capacity` for `capacity_assurance:*`; persist's rules require `infra:attest_assurance` for both (and for `transparency_log:cosigned:*`, which matches CC). - **Q3 — `system:*` and the substrate self-reports.** CC rc20 3.4.7: duty `infra:attest`, conferred by the node's owner in the owner-binding. That label confers nothing by CC 3.4.7.1, but it still opens a reserved family, which 3.4.7 says no label does. Not changed here (it needs the owner-binding walk on persist's own emission path); asked.
- **Q4 — `registry` / `verify` (CC 3.4.9 co-stewards).** Earlier form: an accord co-scrub on the key record. Edition 2 has no co-scrub on a `key:record`.
