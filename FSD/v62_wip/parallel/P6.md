## The ruling (coordinator), as applied

- The secrets API is the **LOCAL plane** (RULINGS "Planes": "LOCAL: the Lens envelope, the secrets API").
- Its three tiers are **capabilities** conferred by a live **`self:delegates_to`** row (RULINGS: capability → `self:delegates_to`) **from this node's owner** to the caller's key. Scopes: `secrets:reader`, `secrets:writer`, `secrets:admin`.
  - The conferrer is `admission::owner_of(dir, dir.node_key_id())`: the kernel's owner seat; the node's cosignature on the owner binding is required (read-checked, admission.rs `owner_of` → `kernel_owner_selves(.., Cosign::Required)`).
  - The predicate is `trust_root::owner_granted_scope(dir, caller, owner, scope)`: the same one the serve tier's owner-grant rung reads (trust_root.rs ~4008). It folds tombstones (an entitled `withdraws`), expiry, the envelope `valid_until`, counts only federation-tier rows, and skips a self-grant (read-checked). Not a second spelling.
- **Tier coverage (checked against the scope tables):** none. `admission::scope_covers(held, wanted)` is true only for equality or a `:`-narrowing of `held`. `secrets:admin` / `secrets:writer` / `secrets:reader` are siblings, and `owner_granted_scope` uses exact `scope_contains` anyway (read-checked). So **each route asks for its own token**, and an owner that wants a key to read and write grants both (one row may carry all three: `"scope": ["secrets:reader","secrets:writer","secrets:admin"]`). This is a change from the earlier form, where admin ⊃ writer ⊃ reader.
- **One composite signature per request**, verified under the caller's **live** edition-2 key. The caller's key id must be an edition-2 identity-ref. Liveness is the key plane's own reading: `held_keys_for_kid` + `HeldKeys::liveness(kid, now_ms)`, and only `Live` authenticates. The composite is `record.key.verify(canonical_request(..), sig)`.
- **No role from a self-declared key type** (P4's audit, CC 3.4.7): the caller's `identity_type` is never read, and no `capability_roles` is read. Witnessed: a key whose own record declares `cirislens_secrets_admin` is refused (I3202).
- Which planes: requests are LOCAL. The grant is a replicated `self:delegates_to` statement at federation tier, because `owner_granted_scope` counts only federation-tier rows (`counts_in_capability_walk`, the #502 E5 rule).

## Adoption notes (Server / Agent / Lens): the header change

**Scope: the HTTP surface only.** The in-process PyO3 Engine secrets path (what the Agent uses) is unchanged in v62: it is a process boundary, with no delegation and no request signature. The delegation and the composite signature below apply only to the `secrets-server` HTTP routes, which have no current caller (coordinator, confirmed with Agent and Server). So no `node`-typed key calls the secrets API, and Q1 below is closed with no node exception.

Routes, query strings, JSON bodies and responses are unchanged. What a caller sends changes:

| | earlier form (≤ v61) | v62 |
|---|---|---|
| key id header | `x-ciris-signing-key-id: <federation_keys.key_id>` | `x-ciris-signing-key-id: <edition-2 identity-ref, urn:ietf:params:oauth:ckt:sha-256:…>` |
| signature | `x-ciris-signature-ed25519` + `x-ciris-signature-ml-dsa-65` (bound hybrid, over the body only) | `x-ciris-signature: base64(composite)`: ONE ML-DSA-65-Ed25519 composite (3373 bytes) |
| signed bytes | the raw body (`""` for GET/DELETE) | `canonical_request(method, path_and_query, body)` (below) |
| authority | `capability_roles` on the key record (`cirislens_secrets_reader/_writer/_admin`) | a live `self:delegates_to` from the node's owner to the caller, scope `secrets:reader` / `secrets:writer` / `secrets:admin` |
| tiers | admin ⊃ writer ⊃ reader | none implied: grant each scope the key needs |

```text
canonical_request = "ciris-persist:secrets-request:v1"
  || u32be(len(method)) || method                   e.g. "GET", as sent
  || u32be(len(path_and_query)) || path_and_query   origin-form target as sent, e.g. "/api/v1/secrets?limit=10"
  || u64be(len(body)) || body                       raw body bytes; empty for GET/DELETE
```

- Rust callers: `ciris_persist::secrets::wire::canonical_request` and `LocalSigner::sign_composite`, or just `FederatedSecretsClient` (it does both).
- Python/other callers: sign those bytes with the composite (`CompositeSigningKey::sign`), base64 standard alphabet, padded.
- A request still carrying either component header is refused (`secrets_signature_earlier_form`), even beside a valid composite.
- **Operator setup on the node:**
  1. the host sets the node identity (`set_node_key_id`);
  2. the node has a live owner binding (with the node's cosignature);
  3. the owner signs a `self:delegates_to` to each caller's edition-2 key, e.g. `{"kind":"delegates_to","scope":["secrets:reader","secrets:writer"]}`, put at federation tier;
  4. revoking access is the owner's `withdraws` of that row.
- **A `node`-typed key cannot be a secrets caller**: `admission::check_node_agency_admission` refuses any non-`infra:*` scope delegated to a key whose record holds `node` (CC 4.4.3.4.3). Agents and users can be callers. See Q1.
- A caller's key rotation (new kid) needs a new grant: the grant names the kid.
