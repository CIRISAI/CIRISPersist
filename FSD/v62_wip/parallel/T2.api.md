## 1. What a test sees at `put_statement`

`ingest::put_admitted_row` routes a non-composer row of these families to `edition2::typed::put_typed_statement` (after T1's group branch and O1's occurrence branch, before the key plane):

| family | lands in | outcome |
|---|---|---|
| `identity:occurrence_revocation` | `federation_identity_occurrence_revocations` (the JSON form's projection write, `put_identity_occurrence_revocation_local`) | `Row` when admitted; **`Pending`** for a user self short of a strict majority of `self_roster::roster_now` |
| `revocation:{entity_type}:{reason}` | `federation_revocations` through `put_revocation` (the JSON door, under the vouch) | `Row` |
| `takedown_notice:{basis}` (legal bases) | `federation_attestations` through `put_attestation` (envelope projected to the names `notice_row_shape` reads) | `Row` |
| `takedown_notice:steward_purge` | `ceg_statements` only (the JSON row door is held shut, #988; the purge door counts) | **`Pending`** |
| `custody:{kind}` | `federation_attestations` (the custody gate + holding-claim fold read it) | `Row` |
| `key_grant:{axis}` | `federation_attestations` + `project_key_grant_row` (`federation_blob_key_grants` / `federation_stream_dek_grants`) | `Row` |
| `delivery_receipt:{stream_id}` | `federation_stream_delivery_receipts` (the receipt door's JOIN + equivocation steps) and its attestation row (`signed_receipt_at`) | `Row` |
| `cosign:{pending,signature}` | `ceg_statements` only (CC 3.1.3: the hold IS the counted row; P1d "Lands in") | `Voice` |

No new `StatementOutcome` variant (T1's `Pending` is reused).

## 4. Which earlier-form builders can flip

| earlier builder / door | twin | can flip? | note |
|---|---|---|---|
| `fed_revocation` + `put_revocation(SignedRevocation)`, a key revoked by itself | `revocation_statement(k, k, ..)` + `e2::put_statement` | **yes** | Lands in `federation_revocations`; read it by digest (`revocations_for_subject`). A revocation of ANOTHER's key needs the slash conferral, as before. A revocation of a KEY's liveness is `key:revocation` (J0), not this family. |
| `FramedOccurrenceRevocation` / `carrier_row` + `additional_scrubs` | `occurrence_revocation_voice(seed, as_identity, &rev, at)`, one per roster key | **yes** | A user self needs a strict majority of `roster_now`: each roster key signs with `as_identity = true`. A node/agent identity lands on one voice. The earlier `CARRIER_WITHOUT_ROSTER_QUORUM` refusal becomes `Pending`. |
| a `takedown_notice:{basis}:v1` scores row (legal basis) | `takedown_statement(claimant, basis, claimant, ..)` | **yes** | The same gates, including `takedown_authority`. |
| a steward purge notice's founders' cosignatures | `takedown_statement(founder_i, "steward_purge", root, ..)`, one per founder | **partly** | The voices are kept (`Pending`). The purge door (`purge_rows`) still takes a `StewardPurgeNotice`; reading the voices from `ceg_statements` there is cut B's or the purge owner's work. |
| `custody_ack_envelope` + an emitted `custody:ack:v1` row | `custody_statement(device, &sha, size, scope, target, at)` | **yes** | No `expires_at`: a report is live for 72 h. |
| `KeyGrantRow` + `emit_input` / `admit_replicated_key_grant` | `key_grant_statement(signer, &row, at)` | **yes** | `wrapped_dek` rides as the wrap text's UTF-8 bytes. The grant projection runs at the door. |
| a `DeliveryReceipt` literal + `put_delivery_receipt` | `delivery_receipt_statement(sub, stream, epoch, k, &root, at)` | **yes** | A published STH is needed first, as before. **The mapping (CC's ruling):**
- `trusted_by` = the edge's iss.
- `trust_domains` = `trust_classes`, for a Registry grant only.
- `expires_at` = `valid_until`.
- `trust_relationship`: **Registry** when the edge names a community this node holds (a registry's root), else **Direct**.
- `trust_type` is **derived, never a member**: `anonymous` for a `self`-scope edge; `partnered` when the reciprocal edge (key → granter) is held and live; else `temporary`.
- It is recomputed for both ends whenever an edge or its `withdraws` lands.
- No live edge left, and the stored granter's edge retired: the row is expired now.
- A grant the v1.3 shape refuses (self-trust; Registry with no classes) is not projected; the edge stays for `trust_root.rs`'s walk.

**Flips (E1's 6 held trust tests):**

| test | flip |
|---|---|
| `trust_grant_then_lookup_round_trip` | `put_key` both keys; `e2::put_statement(d, &e2::trust_accepts_statement(granter, key, &[], None, "federation", at))`; `lookup_trust(&kid(key))`. `trust_type` is now `temporary` by derivation (not the struct's field). |
| `trust_grant_rejects_self_trust` | **rewrite:** a self edge is admitted as an edge but NOT projected; assert `lookup_trust` is `None`. No refusal is raised. |
| `trust_grant_rejects_registry_without_domains` | **rewrite:** an edge naming a held community with no `trust_classes` is not projected (`None`). |
| `trust_revoke_is_idempotent` | `trust_withdraws_statement(granter, key, &rid(edge), at)`, put twice; the second put is a held row (`Voice`) and changes nothing. |
| `trust_list_filter_by_relationship` | Direct = an edge to a key. Registry = an edge to a held community whose community key has a `federation_keys` row, with classes. **Risk:** a keyless community gets no projected row. |
| `trust_list_include_expired` | an edge with `valid_until` in the past cannot be admitted (K1's window, not after `asserted_at`), so use a withdrawn edge (expired at the withdraws) for the "expired" row. |

**Partnered:** two edges, one from each side; witnessed I3173. **Anonymous:** `cohort_scope = "self"`; witnessed I3175.

## 8. v6: replicating an edition-2 purge; reaping refused-claim bytes

```rust
// steward_purge
pub const EDITION2_STATEMENTS_MEMBER: &str = "edition2_statements";
pub fn edition2_notice_envelope(statements: &[Vec<u8>]) -> serde_json::Value;   // {"edition2_statements": [hex..]}
```

- `purge_rows_edition2` records `notice_jcs` = that object (every held voice) and `cosignatures_json` = `[]`.
- `list_purge_bundles_since` serves it unchanged: the bundle's `notice.envelope` is the object, and `cosignatures` is `[]`.
- `apply_replicated_purge`, on a bundle whose envelope carries the member, does this:
  - it puts each statement through the receiver's own statement door (a refused statement refuses the bundle);
  - it requires one shared row id (`notice_malformed` otherwise);
  - it runs the edition-2 count (`authorise_edition2_at`);
  - then the same selection, digest, counts and admissibility checks as before;
  - it records the header with the receiver's held voices.
- The earlier-form arm is unchanged, and `refuse_earlier_form("purge")` now guards only that arm.
- **Flip:** a test building an edition-2 bundle uses `PurgeBundle { notice: StewardPurgeNotice { envelope: edition2_notice_envelope(&[v1, v2]), cosignatures: vec![] }, .. }`. The `PurgeBundle` literals in `steward_purge_invariants.rs` need no change.
- **`put_blob_edition2`:** a claim refused after the bytes landed reaps them with `BlobWriteStore::delete_blob_unless_claimed` (pub(crate)), when they were not held before the call: the guard and the delete are one transaction, and a blob any `here` claim names is kept. An admitted claim re-stores its bytes if a concurrent reap removed them. A refused claim leaves no bytes (I3178); the guard is witnessed by I3181.
