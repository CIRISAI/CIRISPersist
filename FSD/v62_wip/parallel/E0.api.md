**Status: v1.13 (2026-11-18). Changes are listed at the top, newest first.**

## v1.13 (2026-11-18): keys no seed names (E6, chunk_dag's STH producer)

```rust

pub async fn put_key_for_signer<D: FederationDirectory + ?Sized>(dir: &D, signer: &crate::signing::LocalSigner, identity_types: &[&str]) -> String; // its kid
pub fn key_record_for_composite(key: &CompositeSigningKey, identity_types: &[&str], opts: &KeyRecordOptions) -> Vec<u8>;
pub fn statement_of_with_key(a: &Attestation, key: &CompositeSigningKey, family: &str) -> Vec<u8>;
pub fn is_foreign_kid(s: &str) -> bool;
```
- Each puts the key's SELF-SIGNED edition-2 `key:record` through `put_statement` (default windows, as
  `put_key`) and returns the kid. `put_key_for_signer` signs through the LocalSigner's composite
  (`edition2::produce::sign_row`).
- Registration: if the LocalSigner's `key_id` is a seed whose `kid` is this kid (a
  `tier_ingest::test_support::local_signer(alias)`), it resolves like any seed (`seed_of`, `seed_for`).
  Otherwise the kid is FOREIGN: `row_of_statement` / `admit` hold it (the in-memory door knows it),
  but no seed can be recovered. `seed_of(kid)` returns the kid, and `signing_key` / `seed_for` panic
  naming the fix. Sign its rows with `statement_of_with_key(&literal, &key, &family_of(&literal))`
  (composite), or through the LocalSigner (`produce::sign_row`); then `put_statement`.
- chunk_dag `register_hybrid_producer`: `e2::put_key_for_composite(backend, &signer, &[..]).await`
  in place of the JSON `KeyRecord`; the key's id is the returned kid, not `key_id`.
Witnessed in I2553 (sqlite + pg).

## v1.12 (2026-11-18): P1e payload types and families

- `Ty::Tstrs` (`[* tstr]`, a set): written as text sorted by encoding, de-duplicated, NOT run through
  `kid_or_keep`. It is handled by the codec's catch-all arm, since the variant is not on E0's base
  (an array of text under a member typed by an unnamed variant becomes a set). A `Ty::Any` member
  that is an array of text would also be sorted (BELIEVED harmless: takedown's `perceptual_hash`
  is not an array).
- `call_fingerprint` (with `amendment_digest`, `seat_commitment`, `carried`) converts hex to a digest.
- New families `admission:unit`, `identity_amendment`, `deferral:response:{outcome}`: the codec takes
  their member types from P1's `FAMILIES`. Their `sub` `canonical:sha256:<hex>` survives
  (`kid_or_keep` keeps it). The door enforces the closed member lists, so a literal of these
  families must state exactly their members. Anything else in the envelope (e.g. an `"id"`) is
  refused `edition2_payload_invalid`. `refs.prev` / `refs.target` go in an envelope `refs` map (in
  the mapping's `[2, [-16, "hex"]]` form) or, for `target`, as `references_attestation_id`.

## v1.11 (2026-11-18): THE KEY-WINDOW RULE (corrects v1.6's fixed-instant rule)

CC 2.4.1.1: a node/agent key "ends by its own record, and its rows LAPSE by the rule of its own end".
A node/agent record runs at most 365 days. So any fixture whose rows a node/agent key signs at a
FIXED date stops working within a year of that date, whatever start the key is given.
- **Rows signed by `node` / `agent` keys MUST be NOW-RELATIVE** (`now - Duration::days(N)`), within
  the key's window (default: today − 180 d … + 185 d).
- **Fixed calendar dates are allowed only with keys that have NO end**: `user`, `accord_holder`, or
  any identity set without `node`/`agent` (those records start at 0 and never end).
- `put_key_with(.., asserted_at_ms: Some(fixed))` for a node/agent key is NOT a fix for fixed dates.
  v1.6's advice to use it that way is withdrawn. `put_key_with` remains for deliberate windows:
  expiry, renewal and lapse witnesses.
- Guard: a default-window node/agent key signing outside its window panics at `put_signed` /
  `put_row` with "fixed-instant fixture: a node/agent key's rows lapse with its own record ...
  make the rows NOW-RELATIVE ... or sign fixed calendar dates with a key that has no end (user /
  accord_holder); put_key_with with a fixed start is not a fix." (I2549).

## v1.10 (2026-11-18): the `weight` column is carried (P1)

`statement_of` / `row_of` (and so every seal) write the row's typed `weight: Option<f64>` column into
the payload as the fixed-scale `weight` member, `round(w × 10⁶)` (2.5 → 2_500_000), UNLESS the envelope
already states `weight` (then the envelope's wins, ×10⁶ as a scaled member). Builders that default
`weight: Some(1.0)` (bare_attestation, owner binding, scores_row, ...) now carry `weight: 1_000_000`,
so their row ids differ from v1.9's; read `rid(&row)` as always. This supersedes the v1 note that
"the weight column is NOT carried". Witnessed in I2552.

## v1.9 (2026-11-18): earlier-form helpers resolve a MINTED kid through the map (E6)

`tier_ingest::test_support::seed_for` (behind `sign_envelope`, `hybrid_pubkeys`, `threshold_sign`,
`local_signer`, `hybrid_identity`, `reseal_over` → `actor_reseal` / `reseal_for_scope`, `widen`,
`node_coscrub`, ...) now resolves a kid THIS process minted to its seed through `fixture_switch`'s map
(`seed_of`), never through the string. So `actor_reseal(&row)` / `widen(dir, &row, ..)` on a row signed
under `kid(x)` sign with x's key, the key that kid names, and `scrub_key_id` stays the kid.
An UNMINTED `urn:` string still panics (v1.4 guard). `describe_own` / `describe_for` never sign and
need nothing. Witnessed in I2542 (`hybrid_pubkeys(&kid(x)) == hybrid_pubkeys(x)`; unminted panics).
This supersedes v1.4's "do not pass kid(..) to an earlier-form helper": passing a MINTED kid is fine.

## v1.7 (2026-11-18): async earlier-form scope (E6)


A tokio task-local, so every builder and every flipped async store helper (`register_*`,

- Inside an async scope the task-local wins over the sync `with_earlier_form`/`with_edition2`.
- Usage: `#[tokio::test] async fn t() { e2::with_earlier_form_async(async { ... }).await }`.
Witnessed in I2550.

## v1.6 (SUPERSEDED by v1.11: put_key_with with a fixed start is not a fix for node/agent keys)

- **A test whose rows carry FIXED instants (e.g. `2026-01-01`) MUST register its keys with
  `e2::put_key_with(d, seed, types, &KeyRecordOptions { asserted_at_ms: Some(<= its earliest
  instant), ..Default::default() })`**, or use a `user` key (no end, from 0) where the identity
  type does not matter.
- **Default keys are for now-relative rows only.** The default node/agent window is back to
  `today 00:00 UTC − 180 days … + 365 days` (`NODE_DEFAULT_BACK_DAYS = 180`): a window computed from
  `now` would let a fixed instant fall out of coverage on a calendar date.
- **Guard:** a key whose record is a DEFAULT node/agent window (put by `put_key`/`register_*`, or
  built by a flipped KeyRecord builder with no instant) that signs a row outside the window panics at
  `e2::put_signed` / `e2::put_row` with `"fixed-instant fixture: register the key with put_key_with …"`.
  An explicit `put_key_with` for the same seed lifts it. (`put_attestation` of a flipped row does not
  run the guard: the store refuses there, as waiting / not covered.) Witnessed in I2549.

## v1.5 (SUPERSEDED by v1.6: the 360-day default was reverted)

A row is judged at its OWN `asserted_at`, so its signer's key record must cover that instant.
- **Default node/agent window is now `today 00:00 UTC − 360 days … + 365 days`** (`NODE_DEFAULT_BACK_DAYS`,
  was 180). That covers fixtures dated back to ~2025-11-23 and stays live until today + 5 days.
  `key_row_for_earlier` (the flipped KeyRecord builders) uses the same default.
- `user` / `accord_holder` keys start at 0 and have no end, so they cover every instant. Use them
  when the identity type does not matter.
- **Fixed-instant fixtures older than that:** `e2::put_key_with(d, seed, &["node"], &KeyRecordOptions {
  asserted_at_ms: Some(<= the earliest instant the key signs at), ..Default::default() }).await`
  (the end defaults to that + 365 days). A row asserted AFTER the record's end is refused, so a fixture
  spanning more than 365 days needs a user key or two records (a renewal).
- Confirmed: `kid_or_keep` leaves `sha256:…`, `canonical:…` and 64-hex subjects as text (v1.2,
  witnessed in I2542).

## v1.4 (2026-11-18): NEVER seed from a kid

Every identity-ref begins with the same 32 bytes (`urn:ietf:params:oauth:ckt:sha-25…`), and test
signers seed from the first 32 bytes. Seeding from `kid(x)` would therefore give EVERY key the same
keypair, and nothing would report it. Guards (panic, never silent):
- `fixture_switch` (all seeding goes through one fn): a seed starting `urn:` panics
  ("seed a signer from the seed name, never from kid()"). A kid this module minted is resolved to
  its seed through the process map first (`signing_key`, `seed_of`), never through the string; an
  unminted kid panics.
- `tier_ingest::test_support::seed_for` (behind `hybrid_pubkeys`, `local_signer`, `sign_envelope`,
  `threshold_sign`, `hybrid_identity`, ...): the same assert. **Do not pass `kid(..)` to an
  earlier-form helper.** Pass the seed name, or `e2::seed_of(&kid)`.
Witnessed in I2542.

## 1. The switch

```rust
pub fn emit_edition2() -> bool;                          // DEFAULT ON (per thread)
pub fn with_edition2<R>(f: impl FnOnce() -> R) -> R;      // ON inside f, restored after
pub fn with_earlier_form<R>(f: impl FnOnce() -> R) -> R;  // OFF inside f (until slice F deletes the earlier form)
```

Note for `#[tokio::test]` bodies: the switch is thread-local. A multi-thread runtime's
worker threads see the default (ON). `with_earlier_form` only covers synchronous builder
calls made on the calling thread inside `f`.

## 3. The codec (earlier-form-shaped `Attestation` <-> edition-2 statement)

```rust

pub fn statement_of(a: &Attestation, seed: &str) -> Vec<u8>;
pub fn statement_of_family(a: &Attestation, seed: &str, family: &str) -> Vec<u8>;
pub fn try_statement_of(a: &Attestation, seed: &str) -> Result<Vec<u8>, String>;
pub fn row_of(a: &Attestation, seed: &str) -> Attestation;                 // admit(statement_of(a, seed)) mapped at a.tier
pub fn try_row_of(a: &Attestation, seed: &str) -> Result<Attestation, crate::federation::Error>;
pub fn row_of_statement(statement: &[u8], tier: &str) -> Attestation;      // signer's own key:record held
pub fn try_row_of_statement(statement: &[u8], tier: &str) -> Result<Attestation, crate::federation::Error>;
pub fn signed_row_of(a: &Attestation, seed: &str) -> SignedAttestation;
pub fn admit(statement: &[u8]) -> crate::federation::edition2::door::AdmittedRow;

    -> Result<AdmittedRow, crate::federation::Error>;
pub fn carried_statement(row: &Attestation) -> Option<Vec<u8>>;           // the envelope's ceg_statement, decoded
pub fn voice_of(statement: &[u8], seed: &str) -> Vec<u8>;                 // a further voice: same type/family/sub/payload, signed by `seed`
pub fn composer_of(kind: &str, target: &Attestation, seed: &str) -> Attestation; // withdraws|recants|supersedes, refs.target = rid(target), the target's family
```

What `statement_of` does (the inverse of `ingest::attestation_of`):

- payload = the envelope less `ceg_statement` and the `row` mirror;
- `INSTANT_MEMBERS` (RFC 3339 text) -> POSIX ms; `SCALED_MEMBERS` -> integer x10^6;
- per family, from `edition2::payloads::FAMILIES`: a `Bstr` member (hex) -> bstr; a `Digest`
  member (64 hex) -> `[-16, bstr32]`; `Digests` -> a sorted set of those; an `IdentityRef`
  member -> `kid_or_keep`; `IdentityRefs` -> a sorted unique set of `kid_or_keep`; an `Ms`
  member (text) -> POSIX ms. `evidence_refs`, `carried`, `seat_commitment` are digests on
  every family (Verify's envelope rules);
- `references_attestation_id` (64 hex) -> `refs.target` (`[2, [-16, id]]`), and the member
  is removed (attestation_of writes it back from `refs.target`);
- `cohort_scope`: the row's column, when the envelope states none and it is not the default;
- `subject_key_ids`: the row's column, when the envelope states none (each `kid_or_keep`);
- `asserted_at`: the row's, when the envelope states none (ms);
- `author`: the signer's identity-ref when the envelope names none AND the family is authored
  (a counted family, e.g. `group:roster`, `membership:{stage}`, carries no author);
- header: `iss` = `kid(seed)`, `sub` = `kid_or_keep(attested_key_id)`, row type =
  `attestation_type`, family = `family_of(a)`.

`family_of(row)`: the family the row's `dimension` resolves to (Verify's matcher, the
id Verify compares with header -70002 byte for byte). With no `dimension`:
`delegates_to` -> `self:delegates_to`; a `key:*` shaped row is not a row of this codec
(use section 4). Anything else with no dimension panics naming the row type: use
`statement_of_family`. **A dimension Verify's matcher does not register (open vocabulary,
`test:*`, a refused leaf) is refused by the door (`statement_invalid`: dimension
unregistered / refused). Such fixtures must move to a registered dimension.**

Round trip (I2540): `row_of(a, s)` keeps `a`'s envelope (less `ceg_statement`, `row`,
`author`, `asserted_at`, `references_attestation_id`), type, subject (as `kid_or_keep`),
`asserted_at` (at ms), `expires_at`; `statement_of(&row_of(a, s), s) == statement_of(a, s)`.
The `weight` column is NOT carried by `attestation_of` (a known gap, see E0.md).

## 4. The key plane

```rust

#[derive(Clone, Debug, Default)]
pub struct KeyRecordOptions {
    pub asserted_at_ms: Option<u64>,   // default: user/accord_holder 0; node/agent today 00:00 UTC minus 180 days
    pub valid_until_ms: Option<u64>,   // default: node/agent asserted_at + NODE_KEY_MAX_MS; user/accord_holder none
    pub no_end: bool,                  // force no valid_until (a witness of the refusal)
    pub valid_from_ms: Option<u64>,
    pub signer: Option<String>,        // a seed: a record signed by another key (rotation / owner). Default: self
    pub prev: Option<Digest32>,        // refs.target: the predecessor record's row id (rotation)
    pub extra: Vec<(String, ciris_verify_core::cde::Value)>,  // further payload members (hardware_class, ...)
}

pub fn key_record(seed: &str, identity_types: &[&str]) -> Vec<u8>;
```

`key_row` is what `projection::key_projection` writes into `federation_keys` for that
record: `key_id` = `identity_ref` = `kid(seed)`, the composite's two halves, the identity
set comma-joined, `registration_envelope` carrying `ceg_statement`, `persist_row_hash` = the
record's row id. A `SignedKeyRecord { record: key_row(..) }` offered to `put_public_key` is
NOT how an edition-2 key becomes live; put its statement (section 5).

## 6. The flipped builders (what changes for a caller)

Under the switch (default ON):

- **Attestation builders** (`bare_attestation`, `seal_row`, `owner_binding_attestation`,
  `moderate_delegation_attestation`, `consent_peer_set::grant`, `scores_row`,
  `consent_scope_row*`, `consent_withdraws_row`, `typed_family_row`, `proposal_row`,
  `acceptance_row`, `signed_trust_attestation`, `co_signed_trust_attestation`,
  `occurrence_withdrawal`): same signature, the returned row is `row_of(<the earlier row>,
  signer)`: `attestation_id`/`persist_row_hash` = node-computed id, `attesting_key_id` =
  `scrub_key_id` = `kid(signer)`, `attested_key_id` = `kid_or_keep(subject)`, envelope carries
  `ceg_statement`. Put it through the store with `e2::put_signed(dir, &row)` (or the usual
  `put_attestation`, which routes a carried statement once slice A's routing lands).
  A co-signer (owner binding's node voice) is `voice_of(carried_statement(&row), node)`,
  put with `put_statement` AFTER the row.
- **KeyRecord builders** (`replicated_key_record*`, `expired_key_record`,
  `steward_key_record`, `signed_canonical_record*`, `accord_conferred`,
  `authority_signed_record`, `self_scrubbed_record_signed_at`): same signature, return
  `key_row_with(key_id, <identity types>, ..)` (the read-model shape). Make the key live
  with `put_key_row(dir, &rec)`. The `key_id` argument is the SEED; the record's
  `key_id` is `kid(seed)`. Roles/capability lists are not carried (edition 2 has none).
  `expired_key_record` -> a node record whose end is in the past.
- **Typed-plane builders** (`sign_family`, `sign_community`, `family_naming_held`,
  `community_naming_held`, `sign_*_membership_{revocation,widening}`,
  `sign_*_by_consensus`): NOT flipped (no edition-2 typed projection onto
  `SignedFamily`/`SignedCommunity`/membership structs exists on the base). They keep
  emitting the earlier form. Statement twins for the edition-2 path:

  Each further roster member's voice is `voice_of(&st, member_seed)`.
- **Made private**: `sign_widening_by_consensus`, `sign_family_widening_by_consensus` (zero
  external callers). `reverse_quorum::test_support::signed_row` flips through its seal, but
  `reverse_quorum` is refused in v62 (RULINGS "Kernel departures"): its tests are
  delete-candidates for their owners.
- **Every `seal_row` / `seal_row_in_place` / `reseal` caller flips**, builder or not: the seal
  is `row_of(row, signer)`. `reseal(&mut row)` on an edition-2 row works (the signer is the
  row's kid, resolved back to its seed). `sign_envelope` is unchanged (earlier-form triple):
  a literal that is signed with `sign_envelope` and put WITHOUT a seal stays earlier-form;
  rewrite it as `e2::row_of(&literal, signer)`.
- A literal whose `references_attestation_id` is not a 64-hex row id panics in the codec
  ("name the target by rid(&target)").
