# K1 API (published for O1 and others)

**CHANGED (argument order, per the lead's final ruling):** the signature is now `within_record(at, from, until)`. It was `(from, until, at)`.

## `within_record` — the one boundary of a record's window (CC ruled: half-open everywhere)

```rust
// src/kernel/key_end.rs   (module `crate::kernel::key_end`, `pub mod key_end` in `pub mod kernel`)
/// Does a record stating `[from, until)` cover `at`? `from <= at && (until is None || at < until)`.
/// All instants are POSIX ms (u64). `until: None` = no stated end.
#[must_use]
pub fn within_record(at: u64, from: u64, until: Option<u64>) -> bool;
```

- Call as `crate::kernel::key_end::within_record(at, asserted_at, valid_until)`.
- Use it for every coverage reading: key liveness, the key-of-issuer chain's predecessor record covering a rotation, and an occurrence window. Do not redefine it.

## Refusal token

`crate::federation::malformed_row::VALID_UNTIL_NOT_AFTER_ASSERTED_AT` = `"valid_until_not_after_asserted_at"`.

- It is appended to `malformed_row::ALL`.
- It is raised at the edition-2 door (`edition2::door`) for any statement whose payload states `valid_until <= asserted_at`.
- The check is `pub fn check_valid_until_after_asserted_at(payload: &Value, asserted_at: u64) -> Result<(), Error>` in `src/federation/edition2/door.rs`.
