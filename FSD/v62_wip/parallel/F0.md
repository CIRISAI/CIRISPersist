## 1. The gate: `scripts/earlier_form_doors.py` and `scripts/earlier_form_doors.tsv` (new)

The gate is from-disk Python and runs no cargo. The docstring is the full grammar; the summary follows.

### The inventory is found, not listed

| surface | what is inventoried |
|---|---|
| trait | Every `FederationDirectory` method whose parameters name an object type: `Signed*`, `LineageHeadCosign`, `AccordQuorumEvidence`, `GenesisBundle`, `WholenessWitness`, `Accord{Proposal,Participation,Decision}`, `StewardPurgeNotice`, `AdmitSpec`, `RevokeSpec`, `GroupSupersedeProof`, `serde_json::Value`, or a `*json*` parameter. |
| PyO3 | Every `#[pymethods]` / `#[pyfunction]` fn that calls an inventoried trait door, or names a `Signed*` type, or calls an earlier-form verifier (`verify_hybrid*`, `verify_key_registration`, `verify_proof_of_possession`, `verify_record_signed_by`, `verify_row_hybrid_signature`, `verify_signed_*`), or is a write verb that takes a `*json*` parameter. |
| capsule | Every `DirectoryOp` variant whose fields name an object type. Its body is its arm in `dispatch_directory_op`, and `A \| B =>` arms are understood. Arms of other matches (D2's classifier, the proxy's constructors) are not doors. |
| HTTP | Every non-GET route handler in `src/server/*.rs`. |

### Each row's verdict

- `refuses`: a `>`-chain of hops to `refuse_earlier_form(_row)`.
  - A hop is `path.rs::fn`, `trait:<door>` or `trait:*`. `trait:*` means the body calls at least one inventoried trait door, and every one it calls is verified.
  - An empty route means the door's own body refuses.
  - `a | b` lists two chains, and both must hold.
- `edition2`: the chain (or the body itself) calls `put_statement`, `apply_replicated_statement`, `admit_row` or `require_statement_form`.
- `retired`: the door names `EnvelopeKindRetired` and reads nothing (no `from_str`, no verifier, no trait door).
- `exempt`: no route, and the reason must be written in the row.

The gate is red in each of these cases:
- an inventoried door has no row;
- a row names a door that does not exist (stale);
- two rows name the same door.

### Reachability rules

- Each hop must be called from the previous body.
- From a federation or store body, the call must sit at the body's top level: not in an `if` or `match` branch, a closure, or a `&&` / `||` operand. A call in an `if` condition or a `match` scrutinee counts as unconditional.
- The dispatch layers (`src/engine.rs` and `src/ffi/`) only need to make the call somewhere in the body, because they dispatch per backend and inside closures.
- The refusal itself must always be at the top level.
- A trait door is checked on sqlite and on postgres: the override's body if the backend overrides it, otherwise the trait's default body.
- A host door (PyO3, capsule) that calls any trait door the gate has not verified is red, whatever route its row gives.

### Test code

- Comments and literals are blanked first.
- A test-only cfg is **evaluated**, not pattern-matched. P is test-only when it cannot hold with `test` false. So `all(feature = .., test)`, `any(test)` and `all(test, ..)` are test code, while `any(test, feature = ..)` and `not(test)` are production.
- `#[test]`, `#[tokio::test(..)]` and `#![cfg(test)]` mark test code.
- So does a file whose `mod` is declared under a test-only cfg; the declaring parent is resolved lazily up the module tree.
- A cfg that names `test` but does not parse is red, because the gate cannot tell test code from production in that file.

### Commands

| command | what it does |
|---|---|
| `check` | The gate. |
| `list` | The inventory with each door's row. |
| `--self-test` | 37 fixture cases. Each negative names the red it must produce. |
