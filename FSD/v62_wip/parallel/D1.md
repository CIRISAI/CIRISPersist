## Rulings (team lead, recorded)

1. `put_identity_occurrence_json` stays GATED. In the clean mesh, standing comes only from edition-2 statements, so an unsigned occurrence written into the federation plane cannot carry over. After F, the Server writes occurrences as signed edition-2 rows through `put_edition2_statement`. The lead is confirming with the Server that it can sign them. If it cannot, the fallback is a node-local occurrence store that never replicates, and that decision is synthesis's.
2. `put_accord_{proposal,participation,decision}_json` are NOT node-local. CC rc20 removes the accord's proposal, participation and decision; a roster change is a later genesis bundle. The gates stay, and slice F deletes these three PyO3 doors together with their Rust doors.

3. No generic Python `sign_row` in v62. The producers live in persist (cut B), and a host should not sign arbitrary rows with the node key. If an adopter needs one, it gets added as a named, family-scoped producer. This closes the "`sign_row` / `sign_composite` PyO3" item under "Not done".
4. `local_sign_hybrid`, `verify_hybrid` and `verify_signed_*` (the earlier-form signing and verifying methods) are removed in F: composite only, via the producers. F0 owns the deletion; D1 does not touch them.
