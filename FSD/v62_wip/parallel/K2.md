## 1. What was deleted, and the kernel verdict that covers it

### 1a. The single-owner gate (`check_single_node_owner_admission`, KERNEL_SEAMS B1 / C557)

**Deleted:** the `NodeAlreadyOwned` refusal at the door.

**Kernel coverage (read-checked):**

- Since pass 1, `owner_of` → `kernel_owner_selves(.., Cosign::Required)` → `kernel::owner::owner_holders`, which is `Seats::holders("owner", Obj::Key(node))`.
- A binding counts only if the node's key is among its verified scrubs (`owner_rows`, `node_cosigned`).
- Two counted selves → `AmbiguousNodeOwner`, which is fail-closed.
- An uncosigned binding seats nothing.

So the gate's refusal is now "held; the seat reads the node as unowned". That is ruled B1: any count other than one is unowned.

**Kept from the old gate, as two direct calls in `plan_put_attestation`:**

- `admission::check_owner_binding_roster_fresh` (new). This is the roster W bound (`check_roster_act_fresh`, `asserted_at_stale`, #1049).
  - It is now judged against the **kernel's** owner selves, not the pre-kernel fold.
  - B5 (W at the signed instant, first-held row-local) is not a kernel conclusion yet, so the bound stays.
  - I1142 still witnesses it unchanged.
- `ownership_reclaim::check_post_reclaim_rebinding_admission` (unchanged body, CC 3.2 ceremony step 4).
  - The kernel's cosign rule already makes an uncosigned rebinding inert, so this refusal is now redundant with the kernel.
  - I kept it because deleting it retires `ReclaimRefusal::FreshBindingNotCosignedByNode`, and the test `refusal_tokens_are_closed_and_cover_every_ceremony_step` requires step 4 to be named.
  - It is a candidate for the next pass.

**`live_owner_binding_granters`** is now `#[cfg(any(test, feature = "test-anchor"))]`. Its only callers are the differential reference, the bench's `owner_of_pre_kernel`, and the profile hook.

**`AmbiguousNodeOwner` stays an `Err`.**

- B1 says it "becomes the verdict unowned, not an Err".
- Every consumer already treats it as unowned and fail-closed (register `OwnerAmbiguous`, transport_routes, self_collective, at_rest_cascade, announced_owner_state).
- Flipping it to `Ok(None)` would silently widen register.rs's `OwnerAmbiguous` refusal into the unowned path. **Left for a ruling.**

## 4. The canary `kernel_still_needs_own_withdrawal_filter`: KEPT (still passes)

Evidence (read-checked) is ciris-kernel at tag `kernel-v0.2.0` (Cargo.lock `78b2f677`), `crates/ciris-kernel/src/seat.rs`:

- `:1001-1003`: a `Withdraw` concludes when `signed_by(target, signer)`. The node is the presented signer of a cosigned binding, so its withdrawal concludes.
- `:443-447`: `off_ended(o, k)` ends the offer when `w.signer() == k || (!o.to().contains(w.signer()) && o.conf() != Some(Conf::Group) && !eq(o))`. For a `Conf::Own` owner offer, the node is not in `to` (only the owner is), so the node's withdrawal ends the seat.

The kernel therefore still needs persist's own-withdrawal filter, and the canary's final assertion still holds.

The cargo checkout's newer commit `07ced1f` (version 0.1.0 lineage) has the identical `off_ended`. The filter in `owner_rows` stays.
